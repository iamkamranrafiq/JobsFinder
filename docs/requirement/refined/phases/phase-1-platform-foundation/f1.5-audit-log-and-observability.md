## Summary
An append-only audit log of agent and security actions with PII redacted. Structured logging with a correlation id per cycle. OpenTelemetry tracing and baseline metrics and alerts.

## Scope
**In:**
- `AuditLog` entity (append-only)
- Serilog with a PII-redaction enricher
- A correlation id per request and per cycle
- OpenTelemetry traces (API -> worker -> model -> browser)
- Metrics endpoint
- Grafana/Seq setup
- An alert rule for honesty-invariant violations

**Out:**
- User export of the audit log (F5.3)

## Business rules
1. Audited events:
   - auth events
   - profile changes
   - every agent action (input summary, model output reference, outcome)
   - approvals, edits, cancellations
   - settings changes
   - break-glass access
2. PII is redacted in logs: email, phone, CV text, tokens, keys.
3. The audit log is append-only. There are no update or delete paths in code, and the database role for the app cannot `UPDATE` or `DELETE` audit rows. **Only exception:** on account deletion, a documented privileged job, running under a separate role, anonymises that tenant's audit rows. Every run of that job is itself audit-logged (F5.3, Decision D9, 2026-11-22).
4. Retention: 1 year, then purged by a scheduled job.
5. **Honesty alert:** any application marked `Submitted` without a recorded channel confirmation pages the operator immediately.

## Acceptance criteria
1. Given any cycle, then all its log lines and spans share one correlation id.
2. Given a log line containing an email or phone number, then the stored line shows it redacted.
3. Given an attempt to update an audit row through the app's database role, then the database refuses it.
4. Given a simulated `Submitted` without a confirmation, then the alert fires within 1 min.

## NFRs
- Audit write adds < 10 ms p95 to the action.
