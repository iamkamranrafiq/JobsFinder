## Summary
Lock in the Clean Architecture layers and define every provider interface with fake implementations, so later phases only add adapters.

## Scope
**In:**
- Domain / Application / Infrastructure / Api projects (Minimal APIs)
- The interfaces:
  - `IAgentService`
  - `IAIProvider`
  - `IJobSource`
  - `ICvProfileService`
  - `IMatchEngine`
  - `IContentGenerator`
  - `IApplicationChannel`
  - `IBrowserAutomationService`
  - `ICredentialVault`
  - `IEntitlementService`
  - `IApplicationTracker`
  - `INotificationService`
- Fakes for tests
- Migration of the Phase 0 code into these layers

**Out:**
- The real adapters, which arrive in their own feature

## Business rules
1. Dependencies point inward only. Domain and Application never reference EF Core, Playwright, Apify or Anthropic SDKs.
2. Model calls return schema-validated JSON (D1: Sonnet-class for scoring and fields, Opus-class for tailoring and difficult answers).
3. Configuration selects the adapters. Swapping one is a configuration and DI change.

## Acceptance criteria
1. An architecture test fails the build if Domain or Application references Infrastructure packages.
2. The whole loop runs in a unit test using only fakes.
3. The Phase 0 DryRun still works after the migration (regression test).
