## Summary
Accounts with ASP.NET Core Identity. JWT access tokens with rotating refresh tokens, a password policy, lockout, and optional TOTP MFA. MFA becomes mandatory once a mailbox is connected (enforced in F3.6).

## User stories
- As a visitor, I register and sign in so my data is private to me.
- As a user, I enable two-factor authentication to protect my account.
- As a user, I stay signed in on my device without re-entering my password every 15 minutes.
- As the operator, I sign in with a protected operator account so I can run the platform without ever seeing users' data by default.

## Scope
**In:**
- `POST /auth/register`, `/auth/login`, `/auth/refresh`, `/auth/logout`, `/auth/mfa/*`
- Password policy, lockout
- Refresh-token rotation with reuse detection
- Angular login, register and MFA screens; route guards
- An auth-endpoint rate limit
- A minimal **operator role** with mandatory MFA, and an authorization policy for operator-only endpoints *(added 2026-11-22; needed by F5.1, F5.3, F6.1, F6.3, F6.4)*

**Out:**
- Operator features themselves: plan assignment (F5.1), break-glass access (F5.3), the operator dashboard (F6.1 / F6.4) and source administration (F6.3)
- Social login
- Password-reset email delivery (email provider arrives in F2.7; until then reset is out of scope)

## Business rules
1. Passwords: ≥ 10 characters, hashed with Identity's PBKDF2 (or Argon2), checked against a breached-password list.
2. Access token lifetime: 15 min. Refresh token lifetime: 7 days, rotated on every use. Reusing an old refresh token revokes the whole token family.
3. Lockout: 5 failed attempts -> locked for 15 min.
4. Auth endpoints are limited to 10 requests/min per IP.
5. Every feature except the landing page and DryRun demo requires sign-in.
6. Tenant = user (1:1). A tenant is created at registration.
7. **Operator role:**
   - An operator account is separate from user accounts and has no tenant of its own.
   - Operator accounts cannot be self-registered. They are created only by a provisioning command run by the owner.
   - MFA is mandatory for operators from their first sign-in.
8. **Operator-only endpoints** require the operator role. Normal users calling them get 403.
9. **No data by default:**
   - The operator role grants no access to tenant data through normal tenant-scoped endpoints.
   - Per-user data is reachable only through break-glass consent (F5.3).
   - Every operator sign-in and operator action is audit-logged (F1.5).

## Acceptance criteria
1. Given valid details, when I register, then an account and a tenant are created and I am signed in.
2. Given a password < 10 characters or on the breached list, then registration is refused with the reason.
3. Given 5 wrong passwords, then the account is locked for 15 min and a 6th attempt is refused even with the right password.
4. Given an expired access token and a valid refresh token, then `/auth/refresh` returns a new pair and the old refresh token stops working.
5. Given a reused (already rotated) refresh token, then all sessions for that user are revoked.
6. Given MFA is enabled, then login requires a valid TOTP code.
7. Given an unauthenticated request to any protected endpoint, then the response is 401 problem details.
8. Given a signed-in user without the operator role, when they call an operator-only endpoint, then the response is 403 problem details.
9. Given an operator account with no MFA enrolled, when it signs in, then sign-in is refused until MFA is set up.
10. Given a signed-in operator, when they request another user's resource through a normal tenant-scoped endpoint, then no tenant data is returned and the attempt is audit-logged.

## Edge cases
- Login from a second device -> both sessions are valid, each with its own token family.
- The user disables MFA while a mailbox is connected -> refused (F3.6 rule).
- An operator tries to disable MFA -> refused (BR7).
- Someone registers through `/auth/register` and asks for the operator role -> the request is ignored and a normal user account is created (BR7).

## NFRs
- Login p95 < 300 ms (excluding password hashing cost).
- Auth events are written to the audit log (F1.5).

## Dependencies

- F1.5 (audit log)
