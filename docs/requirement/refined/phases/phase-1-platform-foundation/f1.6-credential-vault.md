## Summary
Encrypted storage for the only secrets the platform keeps per user: **mailbox OAuth tokens** and **BYOK keys**. No third-party site logins are ever stored.

## Scope
**In:**
- `ICredentialVault` with envelope encryption (per-tenant data keys)
- `DpapiLocalVault` (dev) and `KeyVaultCredentialVault` (prod)
- Revoke and delete

**Out:**
- The mailbox OAuth flow (F3.6)
- The BYOK UI (F5.2)

## Business rules
1. Secrets are decrypted only in memory at the point of use, and never logged or returned to the client. The API only ever returns a masked hint (e.g. `sk-...a1b2`).
2. Each tenant has its own data key, wrapped by the master key in Key Vault (or Doppler).
3. Supported credential types: `MailboxOAuth`, `ByokAnthropic`. Any other type is rejected.

## Acceptance criteria
1. Given a stored credential, then the database row contains only ciphertext and a key reference.
2. Given a GET on a credential, then only a masked hint is returned.
3. Given a revoked credential, then it is deleted and later uses fail with "credential not found".
4. A unit test fails if any log output contains a credential value.
