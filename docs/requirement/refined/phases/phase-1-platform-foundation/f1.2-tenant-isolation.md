## Summary
Every row of tenant data carries a `TenantId` and is filtered automatically by EF Core global query filters. `JobPosting` and `JobSource` are shared and deliberately not tenant-scoped.

## User stories
- As a user, I can never see or change another user's data.

## Scope
**In:**
- A `TenantId` on all tenant entities
- Global query filters
- Setting the `TenantId` on save
- An `ITenantContext` abstraction that supplies the current tenant. Tests use a fake. The JWT-backed implementation is delivered by F1.1, so this feature does not depend on authentication.
- Automated cross-tenant tests

**Out:**
- Multiple users per tenant (not in v1)
- Moving a tenant to a dedicated schema (later)

## Business rules
1. The `TenantId` is set by the server from the authenticated user. It is never accepted from the request.
2. Shared entities: `JobPosting`, `JobSource`. Everything else is tenant-scoped.
3. Background workers set the tenant context explicitly for each job. A job without a tenant context fails rather than running unfiltered.

## Acceptance criteria
1. **Phase 1 exit:** given two users A and B, when A requests any of B's resources by id, then the response is 404 and no data leaks. This is covered by integration tests on every tenant-scoped endpoint.
2. Given a create request containing a `tenantId` field, then the field is ignored and the server-side tenant is used.
3. Given a background job without a tenant context, then it fails with an error and touches no data.
4. A test enumerates all EF entity types and fails if a non-shared entity lacks a `TenantId` filter.

## Edge cases
- Admin or operator access -> not through normal endpoints; break-glass only (F5.3 / §3.18).

## NFRs
- Query filters add < 5 ms to p95 query latency.

## Dependencies
- F1.4 (architecture skeleton).
- **Build order:** F1.2 is built first. F1.1 depends on it, not the other way round.
- **Exception:** AC1 (the Phase 1 exit test with two signed-in users) can only run end-to-end once F1.1 is done. Until then, the same isolation is tested through the fake `ITenantContext`.
