## Summary
Per-user blocklists of companies and keywords. The user's **current employer**, plus its known parent and subsidiary companies, is blocked automatically.

## User stories
- As an employed candidate, I'm certain the agent will never apply to or show me jobs at my current company.
- As a user, I block companies or keywords I'm not interested in.

## Scope
**In:**
- `GET/PUT /blocklist`
- Adding the current employer from the profile automatically
- An affiliate list (parent and subsidiaries) the user can extend
- Keyword blocks

## Business rules
1. When the profile's current employer is set or changed, its `CompanyKey` is added to the blocklist automatically, marked `CurrentEmployer`.
2. Known affiliates (parent and subsidiaries) are added with it. The user can add more, and can remove any affiliate except the current employer itself.
3. A blocked company's postings are excluded before scoring. They are never shown, scored, queued or applied to.
4. **Block employer** in the review queue (F3.4) adds to the same list.

## Acceptance criteria
1. Given current employer "Acme", then Acme's postings never appear in jobs, the queue or the tracker (tested invariant).
2. Given the current employer is changed from Acme to Globex, then Globex is blocked and Acme remains blocked unless the user removes it.
3. Given the keyword "unpaid" is blocked, then postings containing it are excluded.
4. Given an attempt to remove the `CurrentEmployer` entry, then it is refused while that employer is still set in the profile.

## Edge cases
- E3: a posting at the current employer or an affiliate -> excluded by the pre-filter.
- A company name variant ("Acme Corp" vs "ACME") -> matched through `CompanyKey` normalisation (F2.2).

## Dependencies
- F0.1 (current employer field), F2.2
