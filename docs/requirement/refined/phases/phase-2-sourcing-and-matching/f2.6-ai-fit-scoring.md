## Summary
Score each surviving role 0-100 against the profile, with reasons, gaps and a recommendation, using a Sonnet-class model. Results are cached per (profile version, posting).

## User stories
- As a user, I see why a role fits me (and where it doesn't) before deciding.
- As a user, I can override a score I disagree with.

## Scope
**In:**
- `IMatchEngine` (`AiMatchEngine`)
- The `MatchResult` schema
- Prompt caching of the system prompt and CV
- Batch scoring
- `POST /jobs/{id}/score` (on demand)
- Overriding a score
- Daily scoring cap

## Business rules
1. Output schema: `MatchResult { score 0-100, reasons[], gaps[], seniorityFit, locationFit, rationale, recommend }`. Invalid output is retried at most 2 times, then the item becomes Needs you (`ModelError`) (E20).
2. Default threshold: **70**, configurable per tenant. Roles below it are dropped from the loop but stay browsable.
3. Daily cap: 50 roles scored per tenant (all plans).
4. A score is cached per (profile version, posting). Re-runs do not call the model again.
5. Job descriptions in any language are scored. The reasoning is written in English (E21).
6. A user override is stored next to the model score and is used for gating decisions.

## Acceptance criteria
1. Given a role, then its score, reasons, gaps and a one-paragraph rationale are shown.
2. Given the same role and profile version scored again, then the cached result is returned with no model call.
3. Given 50 roles already scored today, then further scoring waits until the next day.
4. Given a score of 65 and a threshold of 70, then the role does not reach tailoring.
5. Given I override 65 to 80, then the role proceeds to tailoring.

## NFRs
- Scoring 50 roles completes in < 5 min p95 (batched).
- Managed cost contributes to the < USD 0.10 per Submitted application target.
