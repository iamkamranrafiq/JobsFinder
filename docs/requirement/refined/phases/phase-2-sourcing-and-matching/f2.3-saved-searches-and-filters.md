## Summary
Users define saved searches (keywords, locations, remote, salary, visa, seniority). Each saved search drives one cycle per day, or on demand.

## User stories
- As a user, I save "Remote .NET, senior, worldwide" and get matching roles every day.
- As a user, I run a saved search on demand when I want results now.

## Scope
**In:**
- CRUD `GET/POST/PUT/DELETE /searches`
- Filters: keywords, locations, remote (remote / hybrid / on-site), minimum salary + currency, visa sponsorship needed, seniority
- Schedule: daily at a user-chosen hour, in the user's timezone
- On-demand run

## Business rules
1. The default schedule is once per day.
2. An on-demand run is allowed at most once per saved search per hour (rate limit).
3. At most 10 saved searches per user.
4. Filters are profession-neutral. Nothing assumes software roles.

## Acceptance criteria
1. Given a new saved search, then it appears in the list and is scheduled for its next daily run.
2. Given an on-demand run twice within an hour, then the second is refused with 429 and a retry-after time.
3. Given an 11th saved search, then creation is refused with the limit stated.
4. Given a deleted saved search, then its future runs are cancelled. Applications it already produced remain.
