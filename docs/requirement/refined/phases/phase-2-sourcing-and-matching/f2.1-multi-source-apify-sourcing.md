## Summary
Scheduled, shared sourcing from every configured Apify actor: LinkedIn, Indeed, ATS boards, aggregators and niche boards. Each source is scraped once per day for all tenants, within a configurable Apify budget.

## User stories
- As the operator, I add, enable or disable a source by configuration, without a code change.
- As the operator, I switch to a paid Apify token and raise the budget when I get credits.
- As a user, I see fresh jobs from many boards every day.

## Scope
**In:**
- `JobSource` records (actor id, input config, enabled flag, schedule, last run, credit used)
- A daily scheduler
- The shared `JobPosting` store
- Budget meter and alerts
- Per-source off switch
- Per-source failure alerts

**Out:**
- Duplicate detection and freshness rules (F2.2)
- Per-tenant filtering (F2.5)

## Business rules
1. **Accepted risk:** LinkedIn and Indeed are scraped through Apify. Actors never use user accounts, cookies or credentials, and there is no login-wall circumvention.
2. Each enabled source runs **once per day**. Results are shared by all tenants.
3. The Apify token and the monthly sourcing budget (USD) are operator configuration and secrets. The default is the free-tier credit.
4. The operator is alerted at 80% of the budget. At 100%, sourcing pauses until the credit resets or the budget is raised. Scoring and applying continue on the stored postings.
5. A source that fails 3 days in a row raises an operator alert.
6. Each posting records its apply path:
   - `AtsUrl`
   - `Email`
   - `NativeApply` (LinkedIn Easy Apply / Indeed Apply)
   - `Unknown`

## Acceptance criteria
1. Given 3 enabled sources, when the daily schedule fires, then each actor runs once and its postings are stored once (not per tenant).
2. Given a source with `enabled = false`, then it is skipped and its existing postings remain.
3. Given usage reaching 80% of the budget, then the operator alert fires once per period.
4. Given usage at 100%, then no actor runs until the reset or a budget change, and the dashboard shows "Sourcing paused".
5. Given a LinkedIn Easy Apply posting, then its apply path is `NativeApply`.
6. Given a changed token and budget in configuration, then the next run uses them without redeploying the core.

## Edge cases
- E9: credit or budget exhausted -> paused, alerted, stored postings still used.
- An actor changes its output schema -> its items fail normalisation, the run is flagged, and an alert fires.

## NFRs
- Sourcing cost stays within the configured budget (hard stop at 100%).
- One source's daily run processes 1,000 items in < 2 min after the actor completes.
