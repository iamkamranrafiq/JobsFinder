## Summary
Cheap, deterministic filters remove obvious mismatches before any model call. The survivors are ranked so that the daily scoring cap is spent on the most promising roles.

## Scope
**In:**
- Rule filters: location, remote, seniority, language, salary floor, visa, blocklists, already applied
- Ranking by recency, source reliability and rule-match strength

## Business rules
1. Filter order:
   1. blocklists and current employer
   2. already in the applied ledger
   3. `Closed`
   4. the saved search's filters
2. No LLM calls in this stage.
3. Ranking score = recency weight + source reliability weight + rule-match strength. The weights are configuration.
4. Only the top N by rank go to scoring, where N is the tenant's remaining daily scoring cap (50/day).

## Acceptance criteria
1. Given 500 candidate postings and a remaining cap of 50, then only the top 50 by rank are sent to scoring.
2. Given a posting already in the user's applied ledger, then it is filtered out.
3. A test asserts that no `IAIProvider` call happens during pre-filtering.

## NFRs
- Pre-filtering 1,000 postings takes < 1 s.
