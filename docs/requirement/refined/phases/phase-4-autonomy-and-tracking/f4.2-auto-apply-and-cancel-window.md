## Summary
When autonomy allows an auto-submit, it is held for **10 minutes** with an instant notification. The user can cancel it during that window. Only after the window closes does the channel submit.

## User stories
- As a user who trusts the agent, I let it apply automatically, but I still get a chance to stop a bad one.

## Scope
**In:**
- `AutoSubmitPending` state with `cancelUntil`
- `POST /applications/{id}/cancel`
- A scheduler that releases the submit when the window closes
- Notification on hold (F4.5)
- Countdown in the UI

## Business rules
1. Every auto-submit waits exactly 10 minutes from the moment it is ready. While held (`AutoSubmitPending`), it appears in the tracker under **Queued**, with its countdown. *(Ruling 2026-11-22)*
2. Cancelling during the window -> nothing is sent, the item returns to the review queue in state **`Queued`** (not `Cancelled`), and no daily limit is used (E11). *(Ruling 2026-11-22)*
3. At release, all checks run again:
   - the posting is still open
   - the profile version is still current
   - the daily limit is not reached
   - the spend ceiling is not reached
   - autonomy has not been lowered

   If any check fails, the item goes to the review queue, **except the daily limit:** if only the daily limit is reached, the item keeps waiting and is released at the next daily reset (AC4, E7, F4.6). *(Ruling 2026-11-22)*
4. Cancel requests that arrive after release are refused with "Already sent".

## Acceptance criteria
1. **Phase 4 exit:** given scoped auto-apply, then qualifying applications are submitted automatically after the window and within the daily limits.
2. Given I cancel at minute 9, then nothing is submitted and the item is in my queue.
3. Given the posting closes during the window, then at release the item goes to review as "Posting closed".
4. Given the daily limit is reached during the window, then the item waits for the next daily reset (E7).
