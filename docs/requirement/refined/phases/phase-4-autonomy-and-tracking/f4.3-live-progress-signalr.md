## Summary
A SignalR hub at `/hub/agent` pushes cycle and application events to the signed-in user's dashboard in real time. It replaces polling.

## Scope
**In:**
- These events:
  - `CycleStarted`
  - `JobsSourced{count}`
  - `JobScored{jobId,score}`
  - `ApplicationQueued{appId}`
  - `AutoSubmitPending{appId,cancelUntil}`
  - `ApplicationSubmitted{appId}`
  - `NeedsHuman{appId,reason}`
  - `CycleCompleted{summary}`
- Per-user groups
- JWT auth on the hub
- Angular reconciliation with optimistic UI

**Out:**
- A backplane for running several instances (v1 is a single instance, D14)

## Business rules
1. A user only receives events for their own tenant.
2. Workers publish events. The hub only relays them.
3. On reconnect, the client re-fetches state through REST, so no event is assumed to arrive.

## Acceptance criteria
1. Given a running cycle, then dashboard updates arrive < 1 s after each event.
2. Given two users, then neither receives the other's events (test).
3. Given a dropped connection, then after reconnect the dashboard matches the server state.

## NFRs
- Event delivery < 1 s from the event.
