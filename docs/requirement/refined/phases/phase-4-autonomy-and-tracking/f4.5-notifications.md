## Summary
In-app and email notifications for the events a user must act on or should know about, with per-type preferences.

## Scope
**In:**
- `INotificationService` (`CompositeNotificationService`: in-app + email + SignalR)
- `GET/PUT /settings/notifications`
- Notification centre in the UI

## Business rules
1. Notification types and defaults:

   | Type | In-app | Email |
   |---|---|---|
   | Auto-submit pending (cancel window) | always | always, cannot be turned off |
   | Needs you | on | on |
   | Submitted | on | off |
   | Failed | on | on |
   | Daily limit reached | on | off |
   | Spend ceiling at 80% / 100% | on | on |
   | Daily digest | — | F2.7 |

2. Emails contain no CV content.
3. A user can turn off any notification except "Auto-submit pending".

## Acceptance criteria
1. Given an auto-submit enters the window, then an email and an in-app notification arrive within 30 s, with a cancel link.
2. Given I turn off "Submitted" emails, then none are sent, and in-app ones continue.
3. Given an attempt to disable "Auto-submit pending" emails, then it is refused.

## Dependencies
- F2.7 (email provider), F4.3
