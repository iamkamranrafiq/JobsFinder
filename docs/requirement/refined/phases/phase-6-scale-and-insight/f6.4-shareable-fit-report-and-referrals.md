## Summary
Users can share a public "fit report" for any role, and earn managed-inference credit for referring friends.

## Scope
**In:**
- `POST /jobs/{id}/share` producing a public link
- Revoking a link
- Referral codes
- Referral credit added to the managed-inference allowance
- Retention and referral metrics

## Business rules
1. A shared fit report shows the role, company, fit score and reasoning **only**. It never includes CV content, the user's name or contact details.
2. Share links can be revoked and expire after 30 days.
3. Referral credit is granted when the referred user completes their first approved application.

## Acceptance criteria
1. Given a shared report, then the public page contains no CV text or personal data (automated check against the profile fields).
2. Given a revoked link, then it returns 404.
3. **Phase 6 exit:** retention and referral metrics are tracked on the operator dashboard.

## Decisions (2026-11-22)
- **Shared report content (BR1):**
  - The report is a snapshot of the role, company, score and cleaned-up reasoning, taken at share time. The user previews it before publishing.
  - `gaps[]` is left out by default.
  - If the automated check finds CV text or personal data, sharing is blocked. The text is never edited automatically.
- **Share link:**
  - The link uses an unguessable token, is marked `noindex`, and returns 404 once revoked or expired.
  - The public page is a narrow, explicit exception to the rule that every endpoint is authenticated and tenant-scoped.
  - An AC for expiry still needs to be added.
- **Referral credit amount:** stored as an operator setting with no default until pricing is defined (F5.6). No number or price appears in any Story or UI.
- **Credit on the Free plan:** credit builds up as a visible balance, but can only be spent with managed inference. Free users can't use it until the operator assigns a paid plan.
- **Referral abuse:** there is a cap per referrer, no self-referral, and the referred user must verify their email. These rules need ACs.
- **"Approved" (BR3):** approved in the review queue (F3.4), the same definition as the F5.5 activation metric (D14).
- **Retention metric:** weekly cohort retention, where "active" means any signed-in session or cycle.
- **Referral metrics:** codes issued, sign-ups, activated users, credits granted and total credit.
- **Missing ACs:** the referral-code Story (JF-170) and the referral-credit Story (JF-171) need acceptance criteria before they are built.
- **Operator role:** the operator dashboard needs the operator role with MFA, which still needs to be added to F1.1 (JF-14).
