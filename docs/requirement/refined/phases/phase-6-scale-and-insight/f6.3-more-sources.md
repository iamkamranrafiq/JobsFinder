## Summary
Add more Apify actors, driven by source-quality data (F6.1) and the professions users have, for example nursing, accounting and education boards.

## Business rules
1. Each new source is an `IJobSource` configuration (an Apify actor plus a mapping). The core does not change.
2. Each source starts disabled and is enabled after a test run shows normalisation working.
3. All F2.1 rules apply: no credentials, shared daily scraping, budget, off switch.

## Acceptance criteria
1. Given a new source configuration, then it can be enabled without redeploying the core.
2. Given a source whose quality falls below a threshold (for example < 5% of postings above the fit threshold over 30 days), then the operator is prompted to review or disable it.

## Decisions (2026-11-22)
- **Low-quality threshold (AC2):**
  - The threshold is configurable, defaulting to under 5% of postings above the fit threshold over 30 days.
  - The prompt only fires once a source has at least 30 days of data and a minimum number of postings, so new sources aren't flagged on day one.
- **Which sources:** no specific sources are planned now. They will be chosen after launch from the F6.1 source-quality data.
- **Test runs:** a new source's test run does not write to the shared job store until the source is enabled.
- **Budget:** more sources use the Apify budget faster (F2.1). The shared budget meter and its pause at 100% apply to all sources.
- **Operator role:** the review prompt needs the operator role with MFA, which still needs to be added to F1.1 (JF-14).
