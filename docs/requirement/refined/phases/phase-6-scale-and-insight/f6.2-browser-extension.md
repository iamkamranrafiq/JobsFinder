## Summary
A browser extension that captures the job on the current page and sends it to Job-Finder for scoring and tailoring. The user applies on that page themselves, or through a channel if the job has an ATS or email apply path.

## Scope
**In:**
- Capture of job title, company, description and URL from the current page
- Sending it to `POST /jobs/capture`
- Showing the fit score in the extension

**Out:**
- Automating the page (never: the user's browser session is not driven by the agent)

## Business rules
1. The extension reads only the page the user explicitly captures, and only when the user clicks.
2. Captured jobs go through the same duplicate, blocklist and current-employer rules.
3. The extension never automates the user's session or fills forms.

## Acceptance criteria
1. Given I click capture on a job page, then the job appears in Job-Finder with a fit score within 60 s.
2. Given the job belongs to my current employer, then it is rejected with "Blocked: current employer".

## Decisions (2026-11-22)
- **Browser:** Chrome first, using Manifest V3 and the `activeTab` permission only. Edge and Brave use the same build, and Firefox comes later.
- **Where captures live:** captured jobs are stored for the capturing user only. The shared job store is used only to match duplicates.
- **Scoring limits:**
  - A capture counts against the 50-a-day scoring cap.
  - If the cap, the spend ceiling or a missing BYOK key blocks scoring, the job is saved as "score pending", with the reason shown in the extension.
  - The 60-second target (AC1) applies only when scoring is allowed.
- **Authentication:** the extension's sign-in and token handling (scoped, short-lived, revocable) needs an AC before the capture Story (JF-162) is built.
- **Missing ACs:** the capture Story (JF-162) and the score-in-extension Story (JF-165) need acceptance criteria before they are built.
- **New endpoint:** `POST /jobs/capture`.

## Open points
