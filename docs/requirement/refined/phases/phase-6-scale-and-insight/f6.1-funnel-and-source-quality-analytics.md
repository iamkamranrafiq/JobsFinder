## Summary
Analytics for the agent's own funnel and for source quality. There is **no** post-submission outcome analytics (interviews or tailoring wins were removed, Q5/F4).

## Scope
**In:**
- Per-user funnel: sourced -> pre-filtered -> scored -> above threshold -> queued -> submitted, with rates
- Needs-you rate by reason
- Per-source quality: share of postings above threshold, duplicate rate, failure rate, cost per Submitted
- An operator view across tenants (aggregated, no PII)

**Out:**
- Interview, offer or response analytics

## Business rules
1. User analytics only cover the user's own data.
2. Operator analytics are aggregated, with no per-user drill-down without break-glass consent (F5.3).
3. Source quality feeds the source-reliability ranking weight (F2.5).

## Acceptance criteria
1. Given a user's last 30 days, then the funnel shows counts and conversion rates for each stage.
2. Given the operator dashboard, then per-source quality metrics are shown without user identities.

## Decisions (2026-11-22)
- **Source quality and ranking (BR3):**
  - Source quality is measured from the model's fit score, not user overrides.
  - The ranking weight has a floor and needs a minimum sample, so a weaker source isn't starved of scoring and pushed down further.
- **Cost per Submitted:** Apify credit attributed to the source, plus managed-inference cost, divided by the source's confirmed Submitted applications. BYOK usage adds no operator cost.
- **Operator dashboard:**
  - An in-app page behind the operator role and MFA.
  - Groups below a minimum count are hidden, so no single user can be identified.
  - Per-user views only through break-glass consent (F5.3, JF-146).
- **Operator role:** a minimal operator role with MFA is a prerequisite. It still needs to be added to F1.1 (JF-14).
- **Missing ACs:** the Needs-you-rate Story (JF-159) and the ranking-weight Story (JF-161) need acceptance criteria before they are built.
- **Funnel data:** per-stage counts come from durable cycle data, not SignalR events.
