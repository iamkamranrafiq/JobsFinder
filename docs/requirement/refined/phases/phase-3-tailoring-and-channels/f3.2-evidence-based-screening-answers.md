## Summary
Answer application screening questions only from the CV profile and stored preferences, with the evidence behind every answer. Anything unanswerable goes to the user.

## Scope
**In:**
- `ScreeningAnswer { question, answer, sourceEvidence }`
- Answers from preferences (notice period, work authorisation, salary range, "how did you hear about us")
- Drafting free-text motivation answers
- `needs_human` fallback

**Out:**
- LinkedIn data (removed, Q6)
- Diversity questions (F3.3)

## Business rules
1. Every answer carries `sourceEvidence` that points to profile line(s) or a preference. With no evidence, the result is `needs_human`. The model never guesses.
2. Salary: answered from the user's range. If the form forces a single number, or a range outside the user's, the question goes to Needs you (E16). The agent never picks a number.
3. Free-text motivation answers are always shown for review, unless the employer is pre-approved by the user. "Pre-approved employers" is the same list as the F4.1 employer whitelist. *(Ruling 2026-11-22)*
4. "How did you hear about us" is answered from a stored preference (default: "Job board").

## Acceptance criteria
1. Given "Years of C# experience?" and a profile with 8 years, then the answer is "8", with evidence pointing to the skills entry.
2. Given "Do you hold a security clearance?" with no evidence, then the result is `needs_human`.
3. Given a salary field accepting only a single number, then the item becomes `NeedsYou(Salary)`.
4. Given an employer that is not pre-approved, then motivation answers are always queued for review, even at higher autonomy.
