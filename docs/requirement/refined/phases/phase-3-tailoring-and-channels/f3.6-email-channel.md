## Summary
Send tailored applications to the email addresses in postings, from the user's own mailbox (Gmail or Microsoft Graph, send-only OAuth) or through a platform relay. The CV and optional cover letter are attached.

## User stories
- As a user, I connect my Gmail so applications come from my own address.
- As a user, I can disconnect my mailbox at any time.

## Scope
**In:**
- OAuth connect and disconnect (Gmail, Microsoft Graph)
- Send-only scopes
- Platform relay fallback
- Email composition with attachments
- `Submitted` on server acceptance

**Out:**
- Reading the mailbox or tracking replies (removed, Q5)

## Business rules
1. Only send scopes are requested. The platform never reads mail.
2. **Connecting a mailbox requires MFA** on the account. MFA cannot be disabled while a mailbox is connected (D16).
3. Tokens are stored in the credential vault (F1.6).
4. **Submitted** when the mail server (Gmail API, Graph or SMTP relay) accepts the message. A send error -> `Failed(SendError)`.
5. Revoking the mailbox turns queued emails into `NeedsYou(MailboxDisconnected)` (E13).

## Acceptance criteria
1. Given MFA is not enabled, then connecting a mailbox is refused, with a prompt to enable MFA.
2. Given a connected Gmail and an approved email application, then the message is sent from my address with attachments, and the status is `Submitted`.
3. Given the OAuth consent screen, then the only scope requested is send.
4. Given I disconnect my mailbox with 2 emails queued, then both become Needs you.
5. Given the provider rejects the message, then the status is `Failed(SendError)`, never `Submitted`.
