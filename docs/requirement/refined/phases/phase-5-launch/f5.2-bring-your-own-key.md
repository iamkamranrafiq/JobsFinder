## Summary
Users can supply their own **Anthropic** API key. All of their model calls then use it, are billed to them by Anthropic, and do not count against the platform's spend ceiling.

## Scope
**In:**
- `GET/PUT/DELETE /settings/byok`
- Key validation call
- Storage in the credential vault
- Per-call provider routing (BYOK vs managed)
- Optional personal monthly cap

**Out:**
- Other AI providers' keys (later)

## Business rules
1. Only Anthropic keys in v1.
2. The key is validated with a minimal API call before saving. An invalid key is rejected.
3. Only a masked hint is ever displayed.
4. BYOK calls are recorded in the `SpendLedger` as `byok` and are excluded from the managed ceiling.
5. Optionally, the user sets a monthly cap for their own key. When it is reached, model work stops as for the managed ceiling.
6. If the key starts failing (revoked, out of credit), model work stops. The user is notified, and the affected items become Needs you (`ModelError`).

## Acceptance criteria
1. Given a valid key, then it is saved and subsequent model calls use it.
2. Given an invalid key, then saving fails with the provider's reason.
3. Given a revoked key mid-cycle, then the in-flight items become Needs you and the user is notified.
4. Given a Free user with no key, then scoring and tailoring are disabled, with a prompt to add a key.

## Decisions (2026-11-22)
- **D7 - Keyless Free users:** all model-dependent features are disabled for a Free user without a key, including CV parsing and screening answers, not only scoring and tailoring. Onboarding asks Free users for the key first (F5.5).
- **D8 - Personal cap:** the optional monthly cap (BR5) reuses the F4.6 behaviour, including the one-time 80% warning. An AC still needs to be added for it.
