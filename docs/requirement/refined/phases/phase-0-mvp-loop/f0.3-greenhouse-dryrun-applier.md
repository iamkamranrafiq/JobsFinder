## Summary
A Playwright worker opens a Greenhouse application page, fills it from the profile, uploads the CV, and **stops before submit**. It saves a screenshot of the filled form. Nothing is ever submitted in Phase 0.

## User stories
- As a candidate, I see exactly how the agent would fill a real Greenhouse form before trusting it.

## Scope
**In:**
- `IBrowserAutomationService` (Playwright)
- A Greenhouse adapter
- Field mapping from the profile
- CV upload
- A screenshot of the filled form
- The tool-use loop (`read_field`, `fill_field`, `select_option`, `needs_human`)

**Out:**
- Clicking submit (F3.5)
- Other ATS (F3.5)
- Email (F3.6)
- The review queue (F3.4)

## Business rules
1. **DryRun is hard-wired.** The submit control is never clicked in Phase 0, and code paths that could submit do not exist yet.
2. A field that cannot be answered from profile evidence -> `needs_human`. The model never guesses.
3. CAPTCHA, MFA or a login wall -> stop and record `HandedToHuman` with the reason.

## Acceptance criteria
1. Given a Greenhouse posting and a parsed profile, when the applier runs, then all fields the profile can answer are filled, the CV is attached, and a full-page screenshot is stored.
2. Given a required field with no evidence in the profile, then the run ends as `NeedsYou(UnknownField)` with the field label recorded.
3. Given a CAPTCHA on the page, then the run ends as `NeedsYou(Captcha)` and no attempt is made to solve it.
4. In no case is the submit button clicked (verified by an automated test that fails if a submit request is sent).

## Edge cases
- The page fails to load -> `Failed(PageLoad)` after 3 retries with backoff.
- A multi-step Greenhouse form -> each step is filled; the run stops on the final step before submit.

## NFRs
- One DryRun apply completes in < 2 min p95.
