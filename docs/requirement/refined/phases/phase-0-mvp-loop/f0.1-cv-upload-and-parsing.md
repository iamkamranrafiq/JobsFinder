## Summary
A single user uploads a CV (PDF or DOCX). The system extracts its text, asks the model for a structured `CandidateProfile`, and lets the user correct the result. In Phase 0 there is one user and no login. Phase 1 adds accounts.

## User stories
- As a candidate, I upload my CV so the agent knows my real experience.
- As a candidate, I review and correct the parsed profile so nothing wrong is used later.

## Scope
**In:**
- PDF and DOCX upload
- Text extraction
- Model extraction into a profile
- Editable profile form
- Storing the raw file and a versioned profile
- Capturing the current employer

**Out:**
- Multiple CVs per user
- Accounts and tenancy (F1.1, F1.2)
- Diversity (EEO) answers (F3.3)

## Business rules
1. Accepted inputs: PDF or DOCX, ≤ 5 MB, text-based.
2. The profile contains:
   - identity, contact, summary
   - skills (proficiency, years)
   - experience (role, company, dates, achievements)
   - education, certifications, links
   - work authorisation
   - **current employer**
   - preferences (target roles, locations, remote, salary range, notice period)
3. One active profile per user. Every save creates a new profile version.
4. The model output is validated against a JSON schema. An invalid response is retried at most 2 times, then the upload fails with a clear message.
5. The CV is the single source of truth. Later features only use data from the profile.

## Acceptance criteria
1. Given a valid text-based PDF ≤ 5 MB, when I upload it, then a structured profile is shown for review within 60 s.
2. Given a DOCX CV, when I upload it, then it is parsed the same way.
3. Given a scanned/image-only PDF, a password-protected file, a file > 5 MB or another file type, when I upload it, then it is rejected with a specific reason and nothing is stored.
4. Given a parsed profile, when I edit a field and save, then a new profile version is stored and becomes active.
5. Given a parsed profile, then the current employer field is filled in, or left empty for me to complete.
6. The raw file and the structured profile are both stored, and the raw file can be downloaded again.

## Edge cases
- E17: unsupported or oversized file -> rejected with a reason.
- The model returns invalid JSON twice -> the upload fails with "Could not read this CV; try another format", and the raw file is not kept.
- The CV is not in English -> parsed as normal; field labels stay in English.

## NFRs
- Parsing p95 < 60 s.
- Uploads are malware-scanned (from Phase 1 hosting onward; local MVP may skip this).
